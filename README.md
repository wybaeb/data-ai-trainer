# Data/AI Project Trainer

Публичный статический тренажер для обучения запуску `data/AI`-проектов через выбор пилотной метрики, источников данных, стека обработки и маршрута с минимальным временем до доверяемого результата.

Проект специально собран как `GitHub Pages`-friendly сайт:

- без бэкенда;
- без секретов;
- без базы данных;
- без обязательного `npm install`;
- с кейсами, которые лежат отдельно в `data/cases/*.json`.

## Что внутри

- `index.html` - основная страница тренажера.
- `styles.css` - стили интерфейса.
- `app.js` - клиентская логика, загрузка кейсов и расчет маршрутов.
- `data/cases/index.json` - реестр кейсов.
- `data/cases/*.json` - отдельные кейсы.
- `scripts/serve.sh` - локальный запуск через `python3 -m http.server`.
- `scripts/public_safety_check.sh` - быстрая проверка на потенциальные секреты перед публикацией.
- `.github/workflows/deploy-pages.yml` - автопубликация в GitHub Pages.

## Локальный запуск

```bash
cd projects/sber/data-ai-trainer
./scripts/serve.sh
```

После этого откройте:

```text
http://localhost:4173
```

Если нужен другой порт:

```bash
./scripts/serve.sh 8080
```

## Как публиковать на GitHub Pages

1. Создайте отдельный публичный репозиторий и перенесите туда содержимое этой папки.
2. Убедитесь, что основная ветка называется `main`.
3. Выполните локально проверку:

```bash
./scripts/public_safety_check.sh
```

4. Запушьте репозиторий на GitHub.
5. В `Settings -> Pages` включите `GitHub Actions` как источник публикации.

Workflow уже лежит в `.github/workflows/deploy-pages.yml`, поэтому сайт будет публиковаться автоматически.

## Как устроен тренажер

Для каждого кейса участник:

1. выбирает пилотную метрику;
2. видит дерево расчета до финансового эффекта;
3. подбирает источники данных для измеримых сигналов;
4. получает стек обработки, требования к качеству и backlog;
5. сравнивает маршруты по формуле:

```text
Total project days = sum(dev days) + max(time to evidence days)
```

Это упрощенная, но удобная для обучения модель: технические доработки суммируются, а время до доверяемого результата берется по самому долгому сигналу.

## Как добавлять кейсы

1. Создайте новый JSON-файл в `data/cases/`.
2. Добавьте запись в `data/cases/index.json`.
3. Соблюдайте ту же структуру, что и у существующих кейсов:
   - `businessQuestion`
   - `successCriteria`
   - `metricOptions`
   - у каждой метрики: `tree`, `signals`, `choices`

Каждая `choice` описывает реальный источник данных и должна содержать:

- `devDays`
- `evidenceDays`
- `dataCategory`
- `stack`
- `quality`
- `masterSource`
- `backlog`

## Безопасность для публичного репозитория

- Не кладите сюда реальные выгрузки банка, токены, ключи или ссылки с доступом.
- Не используйте `.env` и локальные OAuth-файлы внутри этого репозитория.
- Перед публикацией прогоняйте:

```bash
./scripts/public_safety_check.sh
```

- Все текущие кейсы синтетические и собраны под публичную демонстрацию.

## Идея для QR-кодов

Для практики можно кодировать в QR не главную страницу, а ссылку на конкретный кейс:

```text
https://<your-pages-domain>/?case=legal-contract-review
```

Тогда на слайде участники сразу открывают нужный сценарий.
